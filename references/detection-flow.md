# 检测流程与误报控制

## 一、机械层（脚本可判定）

```bash
node scripts/lint_punctuation.mjs --input <文件> --format text
```

脚本规则见 `gbt15834-audit-matrix.md` 第五节。无法运行 Node 时，按下列清单逐项手查：

1. **半角/英文标点混入中文**：中文之间出现 `, . ! ? ; : ( ) [ ]`。注意排除小数（3.14）、千分位（1,000）、纯英文片段。
2. **引号**：中文里用了英文直引号 `" '`；`“` 与 `”`、`‘` 与 `’` 数量不等。
3. **省略号**：出现 `...`、`。。。`、单个 `…`；或省略号超过两个连用。
4. **破折号**：出现 `--`、`－` 连写；出现单个 `—` 需判断是破折号还是连接号一字线。
5. **重复/超量**：`。。` `，，` 等重复；问号或叹号超过三个。
6. **配对**：`（）《》〈〉【】〔〕` 前后数量不等。
7. **顿号**：数字之间用顿号（可能误用于概数）；并列引号/书名号之间用顿号。
8. **省略号与“等”同现**；**破折号与“即/就是”连用**。
9. **序次语**：`1、`（应为 `1.`）、`（一）、`（应无点号）、汉字数字序次语后用逗号（应为顿号）。
10. **空格**：汉字之间、汉字与标点之间的多余空格。
11. **数值范围**用了 ASCII `~`。

机械层结论只作“线索”，进入语义层前需先排除：代码块、行内代码、网址、Markdown 链接、HTML 标签（脚本已自动忽略）。

## 二、语义层（模型逐条复核）

按下列顺序通读，避免遗漏与重复：

1. **句末点号看语气**：逐句判断陈述/疑问/感叹，核对句末是句号、问号还是叹号。含疑问词但整句不表疑问的，用句号（国标 A.2）。选择问只在末项用问号（4.2.3.2）。
2. **句内点号看层次**：在一句/一段内，标出所有停顿，按“顿号＜逗号＜分号”检查是否由内到外、层次一致。分句内部已有逗号而分句之间仍是逗号时，判断是否该用分号（4.6.3.1）。
3. **冒号**：是否提示下文或总结上文？一句话内是否套用了两个冒号（4.7.3.5）？“说/道”之后是否该用冒号（B.1.5）？
4. **引号**：内层是否用了单引号（4.8.3.4）？引文完整与否，决定句末点号在引号内还是外（B.2.1）？多段引文是否只在末段收尾（4.8.3.5）？
5. **括号**：是句内还是句外（A.8）？括号内的末尾点号是否恰当（B.2.2）？
6. **破折号 vs 括号 vs 冒号**：这个“解释/提示”该用哪个（B.1.7、4.10.3.3）？
7. **省略号**：是否与“等”同用（A.9.2）？前后是否多点了点号（B.2.4）？
8. **书名号**：对象是不是作品名（A.13.1）？并列书名号之间是否多加了顿号（4.5.3.5）？末端的问号/叹号是否放进了书名号内（A.13.5）？
9. **连接号/间隔号**：连接对象决定形式（4.13.3）；月日事件节日的间隔号（4.14.3.5）。
10. **书写形式**：换行处标点是否居行首/行末（5.1.1、5.1.3）。

## 三、误报控制（务必遵守）

- **弹性表述不判错**：国标用“通常/宜/一般”的地方（见 `confusable-pairs.md` 末节），一律降为“建议”。
- **语境优先**：同一符号在不同文体中结论可能不同（如公文与文学）。拿不准时标“待定/建议”，并在报告中说明需要作者确认。
- **不改原意**：任何标点修改都不得改变字词、语序、数字写法、引用内容。
- **一处一次**：脚本与语义层都命中的同一处，只记一条。
- **不臆断**：无法确定的，不写进“错误”清单；宁可少报，不可错报。

## 四、报告产出

按 `report-template.md` 三段式输出。每一处修改必须落到：国标条款号 + 官方示例或官媒案例（取自 `official-cases.md`）。
