## 二、简介文案

**一句话简介（约 50 字）**

> 按国标 GB/T 15834-2011 逐处检查中文标点：哪里错、改成什么、依据哪一条，并附官媒真实案例。

**更短版本（约 22 字）**

> 逐处检查中文标点的错、改法与依据，附官媒案例。

**详细说明**

> 中文标点，日常写、日常读，绝大多数人不成问题。这个工具服务两类人：想把它学明白的人（不限学生），和工作中对文字较真、不能出错的人（体制内材料、媒体、出版、小说写作等）。“这个人其实不知道。”和“这个人其实不知道？”，差一个标点，意思就反了。
>
> 标点校对按 GB/T 15834-2011《标点符号用法》逐处检查，分两层做。先跑确定性脚本，把半角标点混入中文、英文直引号、省略号写成三个英文句点、破折号写成两个连字符、引号括号不配对、概数误用顿号这类形式问题一次列全；再由模型对照判定矩阵复核脚本查不出的语义问题：句末该用句号还是问号，顿号、逗号、分号谁管谁，引号里的句号该放里面还是外面，“说”后面用冒号还是逗号。
>
> 输出固定三段：问题清单、逐处说明、修正全文。每条说明都落到国标条款；凡是人民日报、新华社、央视等官媒公开讲过的同类错误，附上原文案例和出处，改完还能顺手把规则讲明白。
>
> 它只动标点，不改你的字词、数字和文风。国标留有余地的地方（比如并列引号之间用不用顿号）只提建议，不判错误。

## 三、使用场景

1. 公文、简报、总结定稿前通检标点。
2. 公众号、小红书、知乎稿件发布前自查。从 Word 或 AI 生成稿复制过来的文本，最容易混入半角标点和英文直引号。
3. 论文、报告、标书里核对引号内外的句末点号、书名号范围、序次语写法。
4. 带新人时当讲解材料：每处错误都带国标条款和官媒案例，照着讲即可。

## 四、示例问法（触发词）

- 帮我检查这段文字的标点
- 这篇稿子的标点有没有问题
- 引号里的句号该放里面还是外面
- 这句话的标点对不对
- 帮我把这段稿子的标点改规范

## 六、提交前自查

**官方硬性要求**（来自 WorkBuddy 开放平台开发文档）

- 目录结构：`{skill-name}/` 下放 `SKILL.md`，可选 `references/`、`scripts/`、`templates/`。
- `SKILL.md` 用 YAML 信息头加 Markdown 正文；必填 `description`、`description_zh`、`description_en`、`version`、`author`。
- `description` 直接决定用户问什么问题时技能被调起，要写清用途和触发词。
- `references/` 里的文件在 `SKILL.md` 中用 `@references/xxx.md` 引用。
- 不想自动触发时设 `disable-model-invocation: true`；本项目保持默认，允许 AI 自动调用。

**社区实测经验**（第三方文章归纳，官方文档未载，仅供参考）

- 技能包 zip 不超过 20MB（本包约 49KB）。
- YAML 冒号后必须空一格；尽量不用引号；文件名不含空格与特殊符号。
- 提交前先在“设置 → 开发者信息”补齐头像、昵称、简介和联系方式，否则发布会提示“开发者信息待完善”。
- 开发者昵称 2 到 20 个字符，不能纯数字、纯空格或带表情，避开“官方、平台、客服、认证、VIP、第一、测试”这类词。
- 图标建议用矢量图，位图缩略图容易发糊。

## 七、对外口径

- 只处理标点，不改文意、词语、数字和文风；错别字、语法、事实问题不在职责范围。
- GB/T 15834-2011 是推荐性国标，弹性用法只作建议，不判错误。
- 官方案例只取可核验的官方公开来源，不编造案例与链接。
- 涉密、敏感、内部受限文稿请勿上传到在线模型。
